# Нейросеть-корректор терминов (term tagger)

## Что это и что даёт (2026-09-23)
`term_tagger.py` / `tagger_model.py` (MLX, 2,3M параметров) после ASR ставит каждому слову
«оставить / удалить / термин из правых частей replacements.yaml» — текст не генерирует, выдумать
не может. На 100 фразах пайплайн 7,3%/8,6% EPI 55,5% → 6,9%/8,2% EPI 57,6%, ~1 мс. Включение:
`SHEPTUN_TAGGER_PATH=models/term-tagger`; переобучать `sheptun train-tagger` (~13 мин) после
новых правил — список терминов = значения replacements.yaml на момент обучения.
Связано: [[asr-models]], `docs/asr-benchmark-2026-09.md` (четвёртый заход).

## Грабли обучения
- 4 эпох мало (полнота 37%, на тест-сете ноль правок), плато к 20–25-й; вес правок в loss ×2.
- Синтетические опечатки русских слов учат ломать верные формы («логе»→«логи») — русские слова
  портить только реальными искажениями из правил.
- «Частые английские слова из логов» наполовину — ошибки ASR, похожие на слова (`Clod`, `Comid`,
  `CEO`←SEO): как новые цели дают ложные правки (`форк`→`Force`).
- Тест-сет 100 фраз различает только крупные сдвиги: все варианты рецепта в полосе CER 6,8–7,5%.
  Следующий рычаг — реальные пары ошибок GigaAM (сырые фразы лога, исправленные LLM), не синтетика.

## Лог: `Recognized: 'сырой' -> 'обработанный'`
Когда постобработка меняет текст, движок пишет обе версии в одну строку. Сборщики корпуса
(`lm_corpus.read_recognized_phrases`) должны брать левую часть, а не пропускать строку — иначе
теряются именно фразы с ошибками (было 2880 строк).
