# Деплой и перезапуск

## Изменения Python-кода: достаточно restart, пересборка не нужна
`.app`-бандл — тонкая обёртка: лаунчер `MacOS/sheptun` делает `cd` в проект, активирует venv и запускает `python -m sheptun.menubar`, то есть код читается **напрямую из `src/sheptun/`** (пакет установлен editable, `pip install -e`). Поэтому после правок Python-кода достаточно `sheptun restart` — **пересобирать `sheptun install-app` не нужно**. Пересборка требуется только при смене иконки, `Info.plist`, имени бандла или самого лаунчер-скрипта.
Связано: `src/sheptun/app_builder.py:51` (write_executable), команда `sheptun restart`. Важно: настройки читаются один раз при старте (dotenv), поэтому после правки `.env` обязателен `sheptun restart` — иначе живой агент держит старое значение. Всё про вставку текста → [[text-insertion]].

## `sheptun restart` может молча не поднять приложение
Команда делает `pkill` → пауза 0.5s (`PROCESS_KILL_DELAY`, `cli.py:26`) → `open` бандла и печатает
«Sheptun перезапущен», НЕ проверяя, что процесс появился. `open` возвращает успех даже когда
приложение не стартовало — иконка из трея пропадает, а лог молчит. После рестарта проверять:
`pgrep -f sheptun.menubar`; если пусто — `open /Applications/Sheptun.app` повторно.
Вторая грабля диагностики: движок в menubar создаётся **лениво**, при первом включении записи, —
строки `Using <движок> for recognition` и `GigaAM hotwords: …` появляются в логе не при старте,
а после первой диктовки. Не ждать их сразу после `restart`.
