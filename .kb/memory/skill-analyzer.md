# Скилл-анализатор замен (`analyze-replacements-skill` / `skill_analyzer.py`)

Скилл-двойник CLI `sheptun analyze-replacements`: те же окна, промпты и валидация, но модель —
субагенты Claude Code (`replacement-batch`), а не Anthropic SDK. Грабли прогона по всему логу.

## Вывод субагента НЕ виден в терминале пользователя
Строку прогресса печатал `commit`, который запускается ВНУТРИ субагента — stdout субагента до
терминала не доходит, пользователь видит только «Batch N · 4 tool uses · 27k tokens». Поэтому
прогресс печатает ОРКЕСТРАТОР: после каждой группы зовёт `skill_analyzer status --total <N>`
и показывает вывод. То же правило для любой диагностики: то, что должен увидеть человек,
печатает оркестратор, а не субагент.
Связано: `src/sheptun/skill_analyzer.py` (`_cmd_status`), `.claude/skills/analyze-replacements-skill/SKILL.md`.

## Лимит 200 субагентов на сессию обрывает полный проход
Полный проход по логу — ~2970 субагентов при `batch_size=25`, а дефолт Claude Code — 200
(`CLAUDE_CODE_MAX_SUBAGENTS_PER_SESSION`). Прогон вставал на ~6400 окнах из 80700 с «Batch N ·
0 tool uses». Поднято до 3000 в `.claude/settings.json` (`env`) — это НЕ поломка скилла, а
лимит харнесса. Правка `AGENT.md` (tools/effort) и лимита подхватывается только со СЛЕДУЮЩЕЙ
сессии: реестр агентов и settings читаются на старте.
Связано: `.claude/settings.json`, `.claude/agents/replacement-batch/AGENT.md`.

## context_lines НЕ уменьшать, batch_size НЕ поднимать
`context_lines` (±N соседних строк) определяет ТОЧНОСТЬ: по контексту модель отличает искажение
термина от обычного слова. Уменьшать ради экономии агентов нельзя. При этом размер задания
растёт быстро — при `context_lines=5` одно окно ≈ 1.7 КБ: 25 окон ≈ 10k токенов, 50 ≈ 36k,
100 ≈ 67k (столько субагент уже не прочитает). Число окон от `context_lines` НЕ зависит вовсе
(окно строится на каждую строку), так что укрупнять батч без потери качества некуда — рычаг
только лимит субагентов.
Связано: `.claude/skills/analyze-replacements-skill/config.yaml`.

## min_freq поднимать бесполезно — проверено на данных
`min_freq=2` сжимает набор с 80752 окон до 1543 (в 52 раза) и выглядит как идеальная экономия,
НО из 36 реально найденных правил при нём выжило бы ОДНО. Систематическая ошибка ASR
повторяется как фраза, а не как целая строка лога, поэтому фильтр по частоте строки режет
находки почти полностью. Не крутить.
Связано: `src/sheptun/log_analyzer.py` (`ContextWindowBuilder`).
